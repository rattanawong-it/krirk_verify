## การตัดสินใจเชิงออกแบบ

- **รหัสเข้าถึงเก็บ 2 แบบ:** `accessTokenHash` ใช้ตรวจ permalink · `accessTokenEnc` (AES-GCM) ให้ผู้ขอกดคัดลอกลิงก์เดิมจากพอร์ทัลได้ทุกเมื่อ โดยไม่ต้องออกรหัสใหม่
- **คีย์ค้นหาเก็บ 2 แบบ** เหมือนตาราง `Student`: hash สำหรับค้น + ciphertext ให้เจ้าหน้าที่เห็นเลขที่ผู้ขอกรอกจริงใน Phase 4 · ฝั่งผู้ขอเห็นแบบ mask เท่านั้น
- **อนุมัติอัตโนมัติส่งอีเมลเดียว** (แจ้งผลพร้อมลิงก์) ไม่ส่ง "รับคำขอแล้ว" ซ้อนกัน · คำขอที่เข้าคิวได้อีเมล "รับคำขอแล้ว"
- **ตั้งค่าเปิด/ปิด auto-approve** อ่านจาก `AppSetting` `verification.autoApproveEnabled` (หน้าแก้ค่าอยู่ใน F-AUD-06)
- **ไม่เก็บเลขบัตรลง audit log** — metadata มีเพียงเลขอ้างอิง ประเภทคีย์ และผลการตัดสิน

## ข้อจำกัดที่ทราบ / ส่งต่อ Phase ถัดไป

- **คำขอที่รอพิจารณายังตัดสินไม่ได้** จนกว่าจะมีหน้าคิวเจ้าหน้าที่ (Phase 4) — สถานะ `REJECTED` / `NOT_FOUND` และอีเมลแจ้งปฏิเสธจะใช้งานจริงใน Phase 4
- **แจ้งเตือนเจ้าหน้าที่เมื่อมีคำขอเข้าคิว** เป็นแบบสรุปรายวันใน F-NOT-03 (Phase 9)
- **rate limit ต่อ IP ทำงานเมื่อมี `x-forwarded-for`/`x-real-ip`** (หลัง nginx บน production) · บนเครื่อง dev ที่เรียกตรงจะมีเฉพาะ limit ต่อผู้ใช้
- **หน้า permalink ยังไม่มีปุ่มสลับภาษา** — ~~ปุ่มเดิมจะทำให้ `?t=` หลุด~~ (แก้ไขข้อมูล: ปุ่มสลับภาษาเก็บ query string ไว้อยู่แล้ว) · เพิ่มปุ่มแล้วใน Phase 8 (F-UX-08)
- **ยังไม่มี e2e** สำหรับหน้าโควตาเต็ม, permalink หมดอายุ และหน้าจอใหม่บน viewport มือถือ (ตรวจในระดับ unit/logic แล้ว)
- **Dashboard ผู้ขอยังเป็นหน้าชั่วคราว** — สรุปคำขอจริงอยู่ใน F-RPT-01 (Phase 6)
