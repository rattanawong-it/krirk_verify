## 1. Endpoint ที่มี

| Endpoint | Query | ใช้แทนของเรา |
|----------|-------|--------------|
| `GET /StudentApi/StudentStatusReport` | `AcademicLevelId` (int64), `AdmissionTermIds[]` (int64), `StartStudentBatch`/`EndStudentBatch` (int32 รุ่น), `BirthYear` (int32) | `GET /students` (sync เต็มชุด) — แต่ **ไม่มีการแบ่งหน้า** และ **ไม่มี `updatedSince`** |
| `GET /StudentApi/StudentAcademicRecord` | `studentId` (string) | `GET /students/{studentCode}` — แต่คืนข้อมูลคนละรูปแบบ (ผลการเรียนรายวิชา ไม่มีเลขบัตร/สถานภาพ) |
| — | — | `GET /health` **ไม่มี** |

- ยืนยันตัวตนด้วย header **`x-api-key`** (ของเราส่ง `Authorization: Bearer`)
- ทุก response ห่อด้วย envelope `APIResponse` — schema เป็น `Code`/`Message`/`Data`/`HTTPStatusCode`/`IsSuccessful` (PascalCase) แต่ตัวอย่างเป็น `code`/`message`/`data` (camelCase) · `Data` ไม่มี schema กำหนด
- response ที่ระบุไว้: 200, 400, 401

## 3. ข้อกังวลด้าน PDPA

`StudentStatusReport` คืนข้อมูลเกินจำเป็นมาก: ที่อยู่ปัจจุบัน/ตามทะเบียนบ้าน เบอร์โทร อีเมล ศาสนา เชื้อชาติ สถานภาพสมรส ข้อมูลบิดา มารดา ผู้ปกครอง และผู้ติดต่อฉุกเฉิน — spec ข้อ 4.5 และ [`registry-api-spec.md`](registry-api-spec.md) ข้อ 1 ขอเฉพาะชุดขั้นต่ำ

- adapter ต้อง **เลือกเฉพาะฟิลด์ที่ใช้ทันทีหลัง parse** และห้าม log response ดิบ
- `StudentAcademicRecord` มีผลการเรียนรายวิชาและสถานะการชำระเงิน (`statusPaid`) ซึ่งไม่ใช้
- ควรขอฝ่ายทะเบียน/ผู้พัฒนา Keystone ทำ endpoint ที่คืนเฉพาะฟิลด์ตามข้อ 5 ของเอกสารขอ API

## 4. คำถามถึงผู้ดูแล Keystone

1. `code` / `studentId` คือรหัสนักศึกษาจริงหรือไม่ และรูปแบบจริงกี่หลัก
2. ค่าที่เป็นไปได้ทั้งหมดของ `status` — ค่าไหนหมายถึงสำเร็จการศึกษา พ้นสภาพ/ลาออก ถูกเพิกถอนวุฒิ
3. วันสำเร็จการศึกษาอยู่ฟิลด์ไหน (`statusDate` เมื่อสถานะ = สำเร็จการศึกษา?) และรูปแบบวันที่ของ `statusDate`
4. วันสภาอนุมัติปริญญา, เกียรตินิยม, GPAX ในรายการแบบชุด — มีในระบบหรือเพิ่มได้หรือไม่
5. ชื่อปริญญา/คณะ/สาขาภาษาไทย ใน `StudentStatusReport`
6. รายการ `AcademicLevelId` และ `AdmissionTermIds` — ดึงนักศึกษาทุกคนในครั้งเดียวได้หรือไม่ (ไม่ส่ง filter) และจำนวนระเบียนสูงสุดต่อ response
7. มีเวลาแก้ไขล่าสุดของระเบียน หรือ filter ตามเวลาที่เปลี่ยนหรือไม่
8. envelope จริงเป็น camelCase หรือ PascalCase · response เมื่อไม่พบ `studentId`
9. UAT แยกจาก production หรือไม่ (URL ปัจจุบันเป็น `azurewebsites.net`) และ rate limit

## 5. ผลการเรียก API จริง (2026-09-17)

สำรวจด้วยสคริปต์ที่พิมพ์เฉพาะชื่อฟิลด์ ชนิด รูปแบบ (ตัวเลข→9 ตัวอักษร→A) และค่าหมวดหมู่ — ไม่บันทึกชื่อ เลขบัตร หรือรหัสนักศึกษา

### 5.1 การเรียกและการกรอง

| เรื่อง | ผลจริง |
|--------|--------|
| ยืนยันตัวตน | header `x-api-key` ✅ |
| Envelope | **camelCase** `code` / `message` / `data` (ไม่มี `HTTPStatusCode`/`IsSuccessful`) · `code` เป็นสตริง |
| `AcademicLevelId` | **บังคับ** — ไม่ส่งได้ HTTP 400 `code: "422API002"` · `1` = ปริญญาตรี · `2` = ปริญญาโท · `3` = ปริญญาเอก (ยืนยันจากค่า `degree`) · `4` ไม่มีข้อมูล |
| `batch` (รุ่น) | เลข 3 หลัก: **หลักที่ 1–2 = ปี พ.ศ. 2 หลัก · หลักที่ 3 = เทอม (มีแค่ 1–3)** เช่น `641` = ปี 2564 เทอม 1 (ยืนยันโดยผู้ใช้ 2026-09-17) · `0` = นักศึกษาใหม่ที่ยังไม่มีรุ่น (สถานะ "นักศึกษาใหม่" ทั้งหมด) · พบค่าที่เทอมไม่ใช่ 1–3 เช่น `300` (ป.โท 1 ระเบียน) — ไม่ถูกดึง ต้องแก้ที่ Keystone · กรองช่วงด้วย `StartStudentBatch`/`EndStudentBatch` ได้ ✅ |
| ขนาดข้อมูล | ไม่มีการแบ่งหน้า · ป.ตรี รุ่น 611–701 = **12,153 ระเบียน / 36 MB / ~18 วินาที** ในครั้งเดียว · รุ่นเดียว (641) = 1,396 ระเบียน / 4 MB / ~2 วินาที → **sync ทีละ level × รุ่น** |
| `StudentAcademicRecord` | `studentId` = ค่า `code` ของ StatusReport ✅ · ไม่พบ → **HTTP 400** `code: "400API003"` `"Students Not Found"` (ไม่ใช่ 404) |

### 5.2 ค่าจริงที่สำคัญต่อการ mapping

| ฟิลด์ | ผลจริง | ผลต่อระบบ |
|-------|--------|-----------|
| `code` | ส่วนใหญ่ **8 หลัก** · มี 9 และ 12 หลัก · มีค่าตัวอักษรผสม ~20 ตัวอักษรไม่กี่ระเบียน | ต้องเลิกบังคับ 10 หลัก |
| `status` (ภาษาไทย) | สำเร็จการศึกษา · กำลังศึกษา · นักศึกษาใหม่ · นักศึกษาใหม่ลงทะเบียน · ลาพักการศึกษา · ลาออก · ลาออกกรณีอื่นๆ · ลาออกกรณีพิเศษต่อสถาบันอื่น · พ้นสภาพ · พ้นสภาพกรณีขาดการติดต่อ · พ้นสภาพกรณีเกรดต่ำกว่าเกณฑ์ · พ้นสภาพกรณีวุฒิการศึกษาไม่ถูกต้อง | **ไม่มีสถานะ "ถูกเพิกถอนวุฒิ"** |
| `statusDate` | `DD/MM/YYYY HH:mm` ปี ค.ศ. · ปีมีเฉพาะ 2022–2026 · ปีไม่ตรงกับภาคของ `statusTerm` ในผู้สำเร็จการศึกษาส่วนใหญ่ | **ใช้เป็นวันสำเร็จการศึกษาไม่ได้** (น่าจะเป็นวันที่บันทึก/ย้ายข้อมูล) |
| `statusTerm` | `ภาค/ปี ค.ศ. [SEMESTER]` หรือ `[SEMESTER_A]` เช่น `2/2023 [SEMESTER]` | อาจใช้เป็น "ภาคที่สำเร็จการศึกษา" แทนวันที่ — ต้องยืนยัน |
| ชื่อไทย `native*` | ว่างในนักศึกษาต่างชาติบางส่วน (~3%) | ต้องยอมให้ชื่อไทยว่าง แล้วแสดงชื่ออังกฤษ |
| `title` | อังกฤษเท่านั้น (`Mr.`, `Ms.`, `Mrs.`, ยศ) | คำนำหน้าไทยต้องแปลงเองหรือเว้น |
| `citizenNumber` | 13 หลัก · มี 12 หลักบางระเบียน · ว่าง ~20% (ต่างชาติ) | ระเบียน 12 หลักค้นหาไม่ได้ |
| `passport` | รูปแบบปน เช่น `AA9999999`, `A99999999`, ตัวเลขล้วน, `---` | ต้อง normalize และตัดค่าขยะ |
| `degree` / `faculty` / `mainCurriculumName` | **ภาษาอังกฤษเท่านั้น** · มีช่องว่างหน้า/หลังและช่องว่างซ้อน · `degree` บางค่าเป็นชื่อสาขา (`"Arts and Design"`) | ต้อง trim · ชื่อไทยมีเฉพาะ AcademicRecord |
| `department` | เป็น **รหัส** (`BA13`, `IC02`) ไม่ใช่ชื่อสาขา | แสดงสาขาวิชาไม่ได้ |
| AcademicRecord | `faculty`/`facultyEN`, `curriculum`/`curriculumEN` (มีช่องว่างท้าย), `gpax`, `totalCreditCurriculum`, `totalCredit`, ผลการเรียนรายภาค | ภาษาไทย + GPAX ต้องเรียก **รายคน** (หลายหมื่นครั้งถ้าทำตอน sync) |
| เกียรตินิยม · วันสภาอนุมัติ · เวลาแก้ไขล่าสุด | **ไม่มีในทั้งสอง endpoint** | หน้าผลแสดง "—" · sync ทุกครั้งต้องเทียบเนื้อหาเอง |
